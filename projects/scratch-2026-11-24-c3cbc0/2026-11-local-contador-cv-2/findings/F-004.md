## What happened

on Windows the push refused with "Filename too long" for files under records/.vid/, and reported "the bundle's files could not be read"; the repository's own core.longpaths does not reach the temporary clone.

## Evidence

the refused push, then the same push succeeding

## Local workaround

the push re-run with core.longpaths set for that command only (GIT_CONFIG_COUNT); the user's git configuration unchanged.

## Ask

set core.longpaths in the share's own clone on Windows.
